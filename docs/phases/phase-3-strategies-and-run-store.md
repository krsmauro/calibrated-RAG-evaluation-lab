#### 3.5 [x] SQLite run store
Claimed: Claude (Opus 5.5, VS Code session), 2026-11-04
- **Do:** `harness/store.py` with the schema in Design §6 (`runs, retrievals, query_metrics, answers, judgments`). Append-only: no UPDATE of stored results. Writes idempotent on `(run_id, query_id)`. Read-back through Pydantic since the schema can drift.
- **Verify:** test: writing the same row twice leaves one row; reopening the file and reading returns identical data; a schema-version mismatch fails loudly.
- **Refs:** Design §5.8, §6, §9 (Resilience); skill EVAL-CRITICAL-4.
- **Done:** 2026-11-04, Claude (Opus 5.5, VS Code session). `harness/store.py` holds `RunStore`, one SQLite file with STRICT tables `runs`, `run_queries`, `retrievals` and `query_metrics` (long format, NULL for a metric that is not defined). The schema version is `PRAGMA user_version` (1); a file with another version, or a SQLite file that is not a store, is refused on open. Triggers reject UPDATE and DELETE on every table. A run is keyed on its id and a query's results on (run_id, query_id), written in one `BEGIN IMMEDIATE` transaction: the same values again are a no-op, different values under a stored key raise `StoreError` and keep the first. Scores and metrics that are not finite are refused, because SQLite stores NaN as NULL, which would read back as "not defined". Rows are read back through `Run` and `QueryResult`. WAL is on (database rules DB-HIGH-4), and a closed store is one file. `ragcalibrate run` does not use it yet (3.7).
  Evidence: `uv run pytest tests/unit/test_store.py tests/property/test_store_properties.py`: 22 passed. The same run and query written twice, and again after reopening, leave one row in each table; reopening reads back equal values and identical JSON (a negative logit, 0.1 + 0.2, a tie at 0.0, a None metric, an empty FTS ranking); a different run or result under a stored key raises and keeps the first; `user_version` 2 fails with "schema version 2; this code reads version 1 only"; a SQLite file with other tables is refused and left unchanged; all 8 UPDATE and DELETE statements fail with "append-only"; a write that fails after its first rows (a chunk id over 2^63) leaves nothing and frees the key; NaN and infinities are refused; a query without its run fails the foreign key; a closed store leaves no `-wal` file. A Hypothesis round trip over arbitrary text ids, 64-bit integers and finite floats passed 200 examples in the CI profile and 3,000 once by hand. Mutation check, with the bytecode cache off: 13 planted bugs, 12 caught; weakening `BEGIN IMMEDIATE` to `BEGIN` survives, since it matters only with two writers on one file, which no test exercises. `make lint` clean; `make test` 154 passed, also with `CI=1`.
  Files: `src/ragcalibrate/harness/store.py` (new), `tests/unit/test_store.py` (new), `tests/property/test_store_properties.py` (new), this file, `docs/project-plan.md`.
  Deviations: (1) No `answers` or `judgments` tables yet, and no `generator_model`, `judge_model` or `judge_prompt_hash` columns in `runs`: the `/answer` response and the judge's output do not exist yet, and Design §6's `answers.present` is not defined anywhere.
