# Eval sets

Generated by `make evalsets` from the CUAD `data.zip` pinned in `scripts/fetch_cuad.py`.

- `cuad-<split>.queries.jsonl`: what the system under test may be asked (id, document id, question text).
- `cuad-<split>.gold.jsonl`: labels (category, gold spans with raw-text character offsets). Only the harness reads these; the service must never see them (ADR 0005).
- `cuad.manifest.json`: sha256 of each file, the source zip hash, counts, and the `evalset_hash` that identifies this eval set in run manifests.
- `cuad-dev-ci.json`: a fixed sample of 60 dev contracts drawn for PR gating in plan step 4.5. It is **not used by the gate**: the power study (step 4.6, finding F-014) found 60 contracts too few for δ = 0.02, and the gate runs on all of dev (decision D9, `docs/eval-spec.md` section 7). Dev contracts are cut into terciles by length in characters, and within each the contracts with the smallest sha256 of `"{seed}:{id}"` are drawn. The file holds the seed, the size, the `evalset_hash` it was drawn from, the sorted contract ids and `subset_hash`, the sha256 of those ids one per line. It is committed and is not part of `evalset_hash`. To draw another size, change `CI_SIZE` in `scripts/build_evalsets.py` and run `make evalsets`.

The `.jsonl` files are gitignored because they are large (about 19 MB) and regenerate byte for byte; `uv run python scripts/build_evalsets.py --check` fails if what is on disk differs from what the pinned source produces, the CI subset included. Splits follow `docs/eval-spec.md` section 7: CUAD's official test contracts are test, every other contract is dev.
